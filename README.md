# elvira-nails-web

Сайт ногтевой студии и обучения Elvira в Нидерландах. Публичные страницы построены на Next.js, контент кейсов учениц управляется через Payload CMS. Проект разрабатывается командой для реального бизнеса и портфолио.

## Стек и ответственность

| Часть                | Технологии                                        | Назначение                                                                |
| -------------------- | ------------------------------------------------- | ------------------------------------------------------------------------- |
| Сайт                 | Next.js 16, React 19, TypeScript, Tailwind CSS    | Публичные страницы и серверные маршруты                                   |
| Управление контентом | Payload CMS 3.91, PostgreSQL                      | Аккаунты администраторов, кейсы, переводы, фотографии, заявки на обучение |
| Существующий backend | Prisma 7, PostgreSQL, Zod                         | Услуги, бронирование и остальные модели приложения                        |
| Фотографии           | Sharp, локальное хранилище / private S3           | Проверка, обработка и защищённая выдача файлов                            |
| Качество             | ESLint, Prettier, TypeScript, Node.js test runner | Статические и автоматические проверки                                     |

Payload и Prisma используют **разные базы данных**. CMS управляет собственными таблицами и миграциями; существующая база Prisma не становится базой CMS. Supabase при необходимости может оставаться хостингом PostgreSQL существующего backend. Вход в новую админку реализован средствами Payload.

## Что входит в модуль CMS

- Закрытая админка с общей верхней навигацией, аккаунтом владельца и штатными формами Payload.
- Кейсы учениц: история, фотографии, контакты с отдельным разрешением на публикацию, галерея, порядок, черновики и сохранённые версии.
- Четыре языка контента: **NL, EN, RU, UK**, включая украинский.
- Три статуса обучения для кейсов и заявок: **«Учится», «В ожидании», «Закончила»**. Статус обучения не определяет публикацию кейса.
- Публичный список и страницы кейсов в дизайне сайта, галерея с просмотром фотографий.
- Приватная коллекция заявок на обучение, которые администратор вносит и редактирует в CMS.

Автоматический приём заявок с публичного сайта **пока не реализован**: существующая страница `/book-appointment` остаётся заглушкой. Записи и услуги Prisma не синхронизируются с Payload автоматически. Старые кейсы из Prisma также не импортируются автоматически; план переноса описан в документации.

## Локальный запуск

Нужны Node.js 24 LTS, npm и две отдельные PostgreSQL-базы. Docker Compose — необязательный способ поднять локальные базы:

```sh
npm ci
docker compose up -d
```

Создайте настройки по [.env.example](.env.example). Если `.env` уже настроен для команды, сохраните его значения, а переменные CMS добавьте в `.env.local`. Сгенерируйте `PAYLOAD_SECRET` и задайте данные первого владельца по [инструкции CMS](docs/payload-cms.md).

```sh
npm run db:generate
npm run cms:types
npm run cms:importmap
npm run cms:migrate
npm run cms:admin
npm run dev
```

Миграции CMS применяются только к `CMS_DATABASE_URL`. Команда `npm run db:migrate` относится к Prisma и использует `DIRECT_URL`; она не нужна для подключения CMS к проекту с уже настроенной базой приложения.

После запуска:

| Адрес                                      | Назначение                  |
| ------------------------------------------ | --------------------------- |
| `/admin/login`                             | Вход владельца              |
| `/admin/collections/student-cases`         | Управление кейсами          |
| `/admin/collections/training-applications` | Заявки на обучение          |
| `/admin/collections/media`                 | Медиатека                   |
| `/student-cases`                           | Публичные результаты учениц |

## Работа команды

Изменения выполняются в feature-ветках через Pull Request, проверку и code review. В репозиторий не попадают `.env*` с секретами, реальные данные клиентов, пароли, токены, приватные фотографии и дампы production-баз. `.env.example` содержит только шаблоны и данные изолированного локального Docker-окружения.

Для production нужны отдельные базы, приватное файловое хранилище, переменные окружения хостинга и настроенный домен. Локальная папка загрузок не подходит для serverless-развёртывания. Production-развёртывание и перенос реальных данных не выполняются автоматически при установке зависимостей или запуске приложения.
