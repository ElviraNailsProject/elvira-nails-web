# Кейсы учениц

Владелец входит в `/admin/login`, открывает `/admin/collections/student-cases`, создаёт кейс и публикует его штатными средствами Payload CMS. Посетитель видит опубликованные кейсы на `/student-cases` и `/student-cases/:id`.

Запуск, аккаунт владельца и storage описаны в [инструкции Payload](payload-cms.md).

## Структура

```text
payload.config.ts                      сборка конфигурации CMS
src/cms/collections/StudentCases.ts     поля, черновики, права доступа
src/cms/collections/Media.ts            конфигурация загрузок
src/cms/access/                        доступ владельца и публичные ограничения
src/cms/hooks/                         обработка файлов, защита используемых фотографий
src/cms/lib/content-rules.ts           статусы, контакты, правила галереи
src/cms/components/                    расширения штатного интерфейса CMS
src/cms/styles/                        тема и оформление штатных экранов CMS
src/cms/components/admin-header/        верхняя навигация и её стили
src/cms/migrations/                    миграции отдельной базы CMS
src/server/student-cases/              чтение CMS и публичное представление данных
src/features/student-cases/contracts.ts публичные DTO и проверка параметров
src/features/student-cases/public/     публичные компоненты и галерея
```

Next.js обслуживает публичные страницы и admin в одном приложении. Payload отвечает за CRUD, формы, аутентификацию и версии. Публичный адаптер возвращает сайту отдельный DTO; структура административного документа не используется как контракт UI.

## Поля кейса

| Поле                                  | Поведение                                                             |
| ------------------------------------- | --------------------------------------------------------------------- |
| `studentName`, `photo`, `city`        | Имя, портрет и город ученицы                                          |
| `resultTitle`, `story`, `testimonial` | Локализованные описание, история и отзыв                              |
| `status`                              | Только `STUDYING`, `WAITING`, `COMPLETED`                             |
| `_status`                             | Системный статус Payload: `draft` или `published`                     |
| `sortOrder`                           | Порядок карточек на сайте                                             |
| `publishContacts`, `contacts`         | Контакты доступны посетителям только после явного разрешения          |
| `gallery`                             | До 40 фотографий, порядок, видимость каждой фотографии и одна обложка |

В редакторе доступны `nl`, `en`, `ru`, `uk`. Имя, город, статус и фотографии общие для языков; текстовые поля истории переводятся. Публичный адаптер выбирает полный перевод описания и истории: запрошенный язык → EN → NL → RU → UK. В DTO возвращается язык фактически выбранного текста.

На галерею можно назначить только одну обложку, и она должна быть видимой. Повторное добавление одного файла в галерею отклоняется. Описание фотографии для программ чтения с экрана хранится в документе медиатеки.

Контакты поддерживают Instagram, WhatsApp, Telegram, TikTok, email и HTTPS-сайт, по одному контакту каждого типа. Включайте `publishContacts` после согласования с ученицей.

## Публикация и доступ

Черновики, версии, создание и изменения доступны администратору. Payload хранит до 20 версий кейса. Сохранение нового черновика опубликованного кейса не должно подменять текущую опубликованную версию; публикация выполняется отдельным действием CMS.

Публичный сервис обращается к CMS с `overrideAccess: false` без сессии владельца и запрашивает опубликованные документы. Поэтому открытый владельцем сайт получает то же публичное представление, что и посетитель. Скрытые строки галереи и закрытые контакты отфильтровываются также на уровне CMS.

Файл доступен посетителю, пока опубликованный кейс использует его как портрет или видимое изображение галереи. Снятие с публикации закрывает последующие запросы к файлу, если нет другой опубликованной ссылки. Уже скачанное посетителем изображение отозвать невозможно.

Загрузки принимают обычные JPEG, PNG или WebP до 5 MiB и 20 мегапикселей. Sharp декодирует файл, убирает метаданные, учитывает ориентацию, уменьшает до 2400 × 2400 и сохраняет WebP. SVG и анимация отклоняются. Для замены фотографии загружается новый документ медиатеки: это сохраняет прежние изображения в истории версий. Физическое удаление используемого файла блокируется, включая ссылки из сохранённых версий.

## Публичный API

| Метод | Путь                            | Результат                                         |
| ----- | ------------------------------- | ------------------------------------------------- |
| GET   | `/api/student-cases`            | `{ items, pagination }` с опубликованными кейсами |
| GET   | `/api/student-cases/:id`        | `{ data }` с публичным кейсом                     |
| GET   | `/api/cms/media/file/:filename` | Файл с проверкой доступа                          |

Список принимает `locale`, `q` по имени, `status`, `page`, `pageSize`. По умолчанию EN, страница 1, размер 12; максимальный размер страницы — 50. Детальная карточка принимает `locale`. Неизвестные и повторяющиеся параметры отклоняются. Идентификаторы новых кейсов CMS — UUID.

```text
GET /api/student-cases?locale=uk&page=1&pageSize=12
GET /api/student-cases/<uuid>?locale=nl
```

DTO содержит имя, портрет, город, статус обучения, выбранный язык, описание, историю, отзыв, разрешённые контакты и видимые фотографии. Административные версии и служебные поля Payload в него не включаются. Публичные ответы и выдача медиа используют `Cache-Control: private, no-store`.

Административный API теперь находится в `/api/cms`, использует стандартные форматы Payload и его аутентификацию. Старые `/api/admin/session`, `/api/admin/student-cases`, `/api/admin/uploads` и `/api/student-case-media` не являются API новой CMS; новый код не должен их вызывать.

## Перенос прежних данных

Существующие модели и таблицы `StudentCase*` в Prisma не становятся таблицами Payload. Автоматического импорта и двойной записи сейчас нет. Поэтому ранее созданные Prisma-кейсы не появятся в новом публичном списке без переноса.

Для переноса нужен отдельный сценарий: экспорт из исходной БД, загрузка фотографий в приватную медиатеку, сопоставление переводов и контактов, создание кейсов через Local API Payload и проверка результатов. Сначала переносите в тестовое окружение и сохраняйте таблицу соответствия старых ID новым UUID. Если прежние ссылки уже опубликованы, для них потребуются редиректы. Исходные записи удалять для этого не нужно.
