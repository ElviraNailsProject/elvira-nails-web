# Редактор контента студии

Новые экраны повторяют desktop-макет Figma и работают как интерактивный предпросмотр внутри существующей Payload CMS. Это следующий этап интерфейса: подключение этих экранов к публикации контента ещё не выполнено.

## Вход и маршруты

Вход — через `/admin/login`, с существующим аккаунтом администратора CMS. Отдельная регистрация и отдельный пароль для редактора не нужны. Сервер проверяет пользователя коллекции `admins` и право доступа к админке; без авторизации перенаправляет на вход.

Язык интерфейса (RU / UK / EN / NL) меняется в меню аккаунта в хедере или на штатной странице аккаунта Payload. Переводятся подписи, сообщения и элементы управления; введённый контент и примеры записей сохраняют свой исходный текст. Выбор локали контента в форме кейса не меняет язык интерфейса.

| Маршрут                              | Экран                                          |
| ------------------------------------ | ---------------------------------------------- |
| `/admin/studio/promotions`           | Акции                                          |
| `/admin/studio/content`              | Контент сайта, по умолчанию программа обучения |
| `/admin/studio/content?tab=courses`  | Программа обучения                             |
| `/admin/studio/content?tab=services` | Услуги                                         |
| `/admin/studio/content?tab=gallery`  | Галерея                                        |
| `/admin/studio/settings`             | Настройки студии                               |

Верхняя навигация открывает акции, контент и настройки. Аккаунт, медиатека и выход доступны в меню пользователя. Пункт «Записи на приём» пока ведёт к существующей коллекции заявок на обучение.

## Что означает сохранение

- Начальное содержимое — демонстрационные данные макета.
- Новые экраны сохраняют только локальные черновики в `localStorage`, отдельно для каждого ID администратора: `elvira-studio:v1:<ownerId>:<section>`.
- Сохранение, удаление, переключатели видимости и загрузка изображений в этих экранах **не записывают данные в Payload/Supabase и не публикуют изменения на сайте**. Настройки контактов также не меняют отправку писем.
- Черновики доступны только в том же браузере и на том же адресе сайта. На другом устройстве, в другом профиле браузера или после очистки данных они отсутствуют. Несохранённые изменения теряются при уходе со страницы; вкладки браузера не синхронизируют редактируемое содержимое.
- Изображения используются как локальные превью. Ограничения размера и сообщения об ошибках защищают от переполнения хранилища браузера. Сообщение об успешном сохранении появляется только после успешной записи.

Существующие коллекции кейсов учениц, заявок на обучение и медиатеки продолжают работать через настоящий backend CMS. Их сохранение отличается от локальных черновиков новых экранов. Параметры запуска и подключения описаны в [payload-cms.md](./payload-cms.md).

## Границы реализации

Новый редактор рассчитан на ширину окна от **1250 px**. Дизайны планшета и мобильного телефона не реализованы: на меньших экранах выводится пояснение и ссылка на существующие кейсы, прежняя навигация CMS сохраняется.

Маршруты зарегистрированы в `payload.config.ts`; серверная проверка доступа находится в `src/cms/views/StudioViews.tsx`, экраны и общий механизм локальных черновиков — в `src/features/admin-studio/`. Для подключения к сайту следующим этапом нужны модели контента Payload, серверные операции сохранения и публикации, а также загрузка медиа в CMS вместо локальных превью.
