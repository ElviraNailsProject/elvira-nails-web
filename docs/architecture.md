# Архитектура проекта

Проект — одно приложение Next.js с публичным сайтом и Payload CMS. Структура разделяет маршруты, серверную работу с данными и интерфейс отдельных функций.

```text
src/
  app/
    (site)/                  страницы и layout публичного сайта
    (payload)/               подключение Payload, admin и REST API CMS
    api/                     HTTP-маршруты публичного приложения
    components/layout/       существующий хедер публичного сайта
  cms/
    collections/             модели Payload и настройки штатных форм
    access/                  проверка прав доступа
    hooks/                   серверные обработчики CMS
    migrations/              история схемы базы CMS
    views/                   защищённые точки входа в редактор контента
    components/admin-header/ навигация Payload, переводы и стили хедера
    styles/                  шрифты, тема, оформление штатных экранов Payload
  features/
    admin-studio/
      shell/                 общий каркас редактора и вкладки контента
      promotions/            акции: редактор, список, панель, типы и примеры
      courses/               курсы: редактор, карточки, программа и детали
      services/              услуги: редактор, таблица, детали и дополнения
      gallery/               галерея: редактор, сетка, фото и загрузка превью
      settings/              настройки студии и панели формы
      shared/
        drafts/              локальное сохранение черновиков
        ui/                  общие кнопки, поля, переключатели и диалоги
        styles/              общая раскладка и повторяющиеся стили форм
    student-cases/           публичные кейсы, контракты и галерея
  server/                    серверные сервисы и преобразование данных в DTO
  lib/                       общие клиенты и функции приложения
  config/                    настройки публичного сайта
public/
  admin/icons/               SVG с названиями по назначению
  admin/fonts/               используемые шрифты и лицензии
prisma/                      схема и миграции существующего backend
tests/                       проверки правил CMS и серверной логики
```

## Границы ответственности

- `app` соединяет маршруты с модулями. Большие редакторы и бизнес-правила здесь не размещаются.
- `cms` содержит интеграцию с Payload. `views/StudioViews.tsx` проверяет администратора на сервере и только затем показывает клиентский редактор. UI не заменяет серверную проверку доступа.
- `features/admin-studio` содержит интерфейс управления контентом. Компоненты и их `ComponentName.module.css` находятся рядом внутри раздела. Родительский `*Editor` управляет состоянием; дочерние панели получают данные и обработчики через props.
- `*.demo.ts` — начальные данные предпросмотра, `*.types.ts` — типы раздела, `*.model.ts` — чистые правила и преобразования данных. Демонстрационные данные не являются записями базы.
- Общие элементы извлекаются в `shared` только при повторном использовании. Разделы не импортируют внутренние компоненты друг друга; их соединяет `shell`.
- Серверные клиенты, пароли и параметры подключения не импортируются в клиентские компоненты.

## Стили

В проекте используются Tailwind CSS и обычный CSS Modules; Sass не используется.

- На публичном сайте Tailwind применяется для раскладки и небольших локальных стилей компонентов. Например, адаптивная навигация находится в `app/components/layout/Header.tsx`.
- CSS Modules применяются для изолированных стилей сложных компонентов и функций. Они используются в редакторах `features/admin-studio` и публичной галерее `features/student-cases`. Файл `ComponentName.module.css` располагается рядом с компонентом.
- Повторяющиеся стили выносятся в общие модули, например `features/admin-studio/shared/styles/editor-form.module.css`. Не нужно создавать пустой CSS-модуль для компонента без собственных стилей.
- Для нового компонента следует придерживаться основного подхода его раздела и не дублировать одни и те же правила одновременно в Tailwind-классах и CSS-модуле.

`app/globals.css` подключает Tailwind и глобальные стили публичного сайта. `cms/styles/admin.css` подключает глобальные стили CMS: шрифты, переменные темы, переопределения Payload и `AdminHeader.css`, расположенный рядом с хедером. Стили CMS ограничены корневым классом `html.elvira-cms` и не затрагивают публичный сайт.

## Языки интерфейса

Редактор использует язык интерфейса Payload: русский, украинский, английский и нидерландский. Переключатель находится в меню аккаунта. Переводы каждого раздела находятся в его `*.messages.ts`, общие сообщения — в `shared/i18n`. Подписи, ошибки, уведомления и доступные названия элементов используют один механизм перевода. Язык интерфейса не переводит введённые администратором названия, описания и другие данные. Локаль контента в штатных формах Payload — отдельная настройка.

## Данные и публикация

Кейсы учениц, аккаунты, заявки и медиатека используют настоящий backend Payload. Новые редакторы акций, курсов, услуг, галереи и настроек пока используют **локальные черновики браузера**. Они не записывают данные в CMS и не публикуют изменения на сайте. Подробности и маршруты — в [admin-studio.md](admin-studio.md).

При подключении публикации нужно добавить модели и серверные операции в CMS, затем заменить способ загрузки/сохранения в редакторах. Компоненты таблиц, карточек и панелей могут остаться прежними.

## Генерируемые и временные файлы

- Миграции, `package-lock.json`, `cms/payload-types.ts` и Payload `importMap.ts` нужны для воспроизводимой установки и работы CMS. Их размер сам по себе не делает их лишними. `importMap.ts` обновляется командой `npm run cms:importmap` после переноса компонентов.
- Prisma Client в `src/generated`, сборка `.next` и временные файлы `.local` исключены из Git.
- `.local/design-references` хранит только локальные изображения макета и сведения об исходных ресурсах. Они не входят в приложение. Экспериментальные экспорты `desktop-*.tsx` удалены.
- `.local/deployment` содержит локальные настройки запуска и секреты; она исключена из Git и не относится к исходному коду интерфейса.

После изменений выполняются `npm test`, `npm run lint` и `npm run build` (включая TypeScript), затем проверяются затронутые сценарии в браузере.
